## 工作流节点

1. `startup-baseline`：核对 `origin/main`、干净工作区、批准评论、二十四路径和启动 Git 快照。
2. `isolation`：建立 `codex/issue-65-v1.2.43-catalog-reaudit` 独立分支，不修改或删除 `main`。
3. `control-plane`：落盘 Plan、Session Plan、Runtime Workflow 与 Discovery Report；AGOS 只运行 `ReportOnly`，`needs-input` 后立即绕过。
4. `red`：更新仓库级测试为 `v1.2.43` 预期，并增加 Watcher、Provider、User Scripts、广告例外和 Provider fixture 断言；记录真实失败。
5. `green-release`：将五域 feature、五域 contract 与 `source-index` 的 Release 锚点推进到 `v1.2.43`。
6. `green-semantics`：定向更新四个受影响行为域与 Provider fixture，不重写未受影响功能。
7. `green-audit`：把 `source-lock.release_audit.catalog_release` 对齐快照，并清空 stale 字段恢复 `current`。
8. `control-plane-sync`：更新 `AGENTS.md`、`README.md`、`build.md`、Master Plan、Parity README 与本任务证据。
9. `verify`：运行目录测试、CI 脚本测试、仓库政策、范围检查、空白检查和 Git 快照。
10. `delivery`：普通提交、普通推送并创建关联 Issue `#65` 的非 Draft PR。
11. `review-ci`：核验最终 Head Review 对话、标准 GitHub-hosted CI、Artifact 和范围；失败必须先确定根因再修复。
12. `merge-gate`：只报告最终 Head 与证据，等待项目所有者单独授权 Squash Merge。
